# Проект: Прогнозирование заказов такси в аэропортах

## 1. Назначение и цель проекта

Компания такси собирает исторические данные о заказах в аэропортах. Для привлечения достаточного количества водителей в периоды пиковой нагрузки требуется прогнозировать количество заказов на следующий час.

**Цель:** построить модель прогнозирования числа заказов такси на час вперёд.

**Целевое требование к качеству:** значение метрики RMSE на тестовой выборке не должно превышать 48.

## 2. Входные данные

**Источник:** файл `/datasets/taxi.csv`

**Структура данных:**

| Поле | Описание |
|------|----------|
| `num_orders` | Количество заказов такси (целевой признак) |

*Примечание:* временная метка содержится в индексе или отдельном столбце; данные представлены в виде временного ряда с фиксированным интервалом.

## 3. Этапы выполнения

### 3.1. Загрузка и подготовка данных
- Загрузить данные из CSV-файла.
- Выполнить ресемплирование временного ряда с шагом **1 час**.
- Убедиться в отсутствии пропусков; при необходимости применить методы заполнения или интерполяции.

### 3.2. Анализ данных
- Визуализировать временной ряд (общий тренд, сезонность, выбросы).
- Проверить стационарность ряда (при необходимости).
- Выявить характерные паттерны: внутрисуточная и внутринедельная сезонность, пиковые нагрузки.
- Сформулировать выводы, влияющие на выбор признаков и модели.

### 3.3. Формирование признакового пространства
Создать признаки, отражающие временную структуру ряда:
- час суток (0–23);
- день недели (0–6);
- выходной / рабочий день;
- месяц / сезон;
- лаговые значения целевого признака (например, за 1, 2, 3, 24 часа);
- скользящие средние / суммы за окна (например, за последние 6, 12, 24 часа);
- признаки «праздник / предпраздничный день» (по желанию).

### 3.4. Разделение выборок
- Разделить данные на обучающую и тестовую выборки в соотношении **90% / 10%**.
- Сохранить временнýю структуру (не перемешивать, тестовая выборка — последние 10% наблюдений).

### 3.5. Обучение моделей и подбор гиперпараметров
Рассмотреть следующие типы моделей:
- линейная регрессия (базовая модель);
- деревья решений / случайный лес;
- градиентный бустинг (LightGBM, XGBoost, CatBoost);
- (опционально) рекуррентные нейронные сети / LSTM.

Для каждой модели провести подбор гиперпараметров (например, с помощью кросс-валидации с учётом временной структуры, без перемешивания).

### 3.6. Оценка качества
- Основная метрика: **RMSE** (среднеквадратичная ошибка).
- Проверить выполнение требования: RMSE ≤ 48 на тестовой выборке.
- Дополнительно рассчитать MAE для интерпретируемости.

### 3.7. Анализ результатов
- Сравнить качество моделей.
- Выбрать лучшую модель по RMSE.
- Проанализировать остатки (наличие систематической ошибки, гетероскедастичность).
- Сделать вывод о пригодности модели для оперативного использования.

## 4. Выходные результаты

- Обучающий Jupyter Notebook со всеми этапами обработки и моделирования.
- Лучшая модель, сохранённая в формате `joblib` или `pickle` (опционально).
- Значение RMSE на тестовой выборке (не более 48).
- Выводы о характере временного ряда и качестве прогнозирования.
- Рекомендации по внедрению модели в операционный процесс.

## 5. Примечания

- Данные представляют собой временной ряд — перемешивание при кросс-валидации запрещено.
- Ресемплирование должно быть корректным (агрегация суммированием для количества заказов).
- Все преобразования (создание признаков, масштабирование) должны быть выполнены без утечек данных из тестовой выборки.
